# Handoff: walkthrough "$0 fallback" — brand-colored placeholder + never-VO-over-placeholder

Date: 2026-06-23
Scope: Walk Studio pipeline only. Edited `adapters.py` + `orchestrator.py`.
Did NOT touch `studio/editor/`, walk-ultra/promo-agent, `WalkthroughPlayer.tsx`, or any
real-mode capture logic in `walk_native.py`.

Backups: `adapters.py.pre-wtfallback.bak`, `orchestrator.py.pre-wtfallback.bak`.

## The two fixes

### Fix 1 — brand-color the SYNTH placeholder (was fixed teal 0F766E for every brand)
- `adapters.py`: added `_norm_hex(color, fallback)` (strips a leading `#`, validates a
  6-hex triple, uppercases; falls back to `fallback` for missing/garbage input).
- `generate_walkthrough(...)` gained an optional `accent_hex=None` kwarg. On the
  **mock synth branch** it now renders the card with `_norm_hex(accent_hex,
  TYPE_COLOR["walkthrough"])` instead of the hardcoded `TYPE_COLOR["walkthrough"]`
  ("0F766E"). Backward-compatible: no/garbage accent -> historical teal.
- `orchestrator.py` `_walkthrough_gen()` threads the run's brand accent into that call:
  `accent_hex=palette.get("accent")`. `palette` comes from
  `remotion_codegen.palette_for(job["company_url"])` (the CLIENT brand; e.g. Stripe
  `#635BFF`). `palette_for` ALWAYS returns an `accent` (the `_default` has one), so the
  accent is always resolvable; the teal fallback only triggers on a malformed hex.
- The synth result now also carries `"synth_color"` (the hex actually used) and
  `"placeholder": True` (see Fix 2).

### Fix 2 — never ship a real-walkthrough VO over a placeholder (drop the scene)
Reuses the EXISTING non-fatal drop mechanism. The walkthrough slot already drops the
scene when `generate_walkthrough` returns `None` (failed native capture). I extended the
same slot: in a **real** build, if the walkthrough came back as a PLACEHOLDER (synthetic
card or studio storyboard frame, not a genuine capture), drop the scene the same way.

Real-vs-placeholder signal = a new explicit `placeholder` bool on every walkthrough
return dict:
- mock synth card .......... `{real:False, placeholder:True,  synth_color:...}`  -> placeholder
- studio_placeholder() ..... `{real:True,  placeholder:True,  kind:"placeholder"}` -> placeholder
- real native capture ...... `{real:True,  placeholder:False, native:True}`       -> genuine
- cached proven capture .... `{real:False, placeholder:False, cached:True}`        -> genuine (reused real)

Gate (orchestrator walkthrough slot, right after the `info is None` skip):
```
if mode == "real" and isinstance(info, dict) and info.get("placeholder"):
    rec.update(decision="skip", status="skipped", output_path=None, note=...)
    led.event(...); led.upsert_scene(rec); flush(); continue
```
Why `mode == "real"`: mock placeholders are by-design (the $0 studio-scrub / test
build that never ships to a customer; the suite asserts the mock walkthrough still
ships). Only a REAL delivery that fell back to a placeholder is the audio<->visual
mismatch we must avoid.

VO beat drops automatically: the VO aligner builds `produced_offsets` from `clips`
(produced clips only) and drops any beat whose `scene_id` isn't in it (orchestrator
~L688-700). A dropped walkthrough never appends to `clips`, so its narrated beat is
dropped with no extra code. Confirmed: `beats_dropped` includes "walkthrough".

The drop is a CLEAN skip (NOT appended to `warnings`), so the run stays `delivered`
rather than flipping to `completed_with_warnings` (a stubbed/expected fallback is not a
failure). Genuine and cached captures have `placeholder:False` -> gate is False -> KEPT
(scene + VO beat), exactly as before.
