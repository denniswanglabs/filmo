# Editor props-load fix — handoff (2026-06-22)

## Problem
The editor auto-preferred `props.edited.json` over the clean `props.json`, so a
stale verification edit ("Edited live, no LLM") silently shadowed the real
generated title ("Build internet businesses") for run r5-stripe. Editor looked
like it was showing junk.

## Fix (DEFAULT now loads the CLEAN original)
### Root cause — `studio/editor/server-api.js`
- The `/api/props` handler (was L104-113) had:
  `const which = fs.existsSync(edited) ? edited : base;`
  i.e. edited shadowed the original whenever it existed.
- Now: defaults to `base` (props.json). Only returns `props.edited.json` when the
  caller passes `&edited=1` AND it exists. Response now also includes
  `hasEdited` so the UI can offer an explicit "load saved edit" affordance.
- Doc comment at top of file updated to match.

### Front-end — `studio/editor/src/App.jsx`
- `loadRun(id, { edited = false })` — adds `&edited=1` only when explicitly asked.
  Default call sites load the original.
- Top bar: when a run has a saved edit, shows a "Load saved edit" button; while
  viewing the edit, shows "Revert to original" (reloads clean props.json). The
  EDITED pill now keys off `viewingEdited` (source === "props.edited.json"), not
  merely the file's existence — so the pill only shows when you're actually
  viewing the edit.
- `viewingEdited` derived from `source` state; `revertBtnStyle` added.
- After a successful Save, `source` is set to `props.edited.json` and the run's
  `hasEdited` flips true in the runs list, so the pill/toggle stay accurate.
