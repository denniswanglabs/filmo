# Hera click-to-select — handoff (2026-06-22)

HEADLINE feature: CLICK-TO-SELECT scene-graph editing in the Walk Studio editor
(Vite + React + @remotion/player, :3040). Clicking a visual ELEMENT inside the
live preview now SELECTS it — draws a CORAL bounding box and the inspector jumps
to that element — exactly like Hera. git repo, NOT committed. Edited ONLY files
under `studio/editor/`. No emojis. Canonical palette unchanged (coral #D6351C).

## Mechanism (files + approach)
- NEW `src/SelectionOverlay.jsx`:
  - `usePreviewSelection(stageRef, { onPick, onHover, enabled })` — attaches
    CAPTURE-phase `click` + `pointermove`/`pointerleave` handlers on the Player's
    stage container. On click it does `target.closest('[data-scene-id][data-field]')`,
    reads `data-scene-id` + `data-field`, `preventDefault`+`stopPropagation` (so a
    click SELECTS, never toggles play), and calls `onPick`. Hover reports the
    selectable under the cursor for the faint cue + sets `cursor:pointer`.
  - `<SelectionOverlay>` — an absolute layer (`pointer-events:none`, z-index 4)
    over the Player. `useTrackedRect` finds the element by
    `[data-scene-id="X"][data-field="Y"]`, measures `getBoundingClientRect()`
    RELATIVE to the stage, and re-measures via a rAF loop (while selected) +
    on resize + on `frame` change — so the coral box stays glued as the element
    animates/scales. Draws: 2px solid coral outline + soft coral glow + 4 white
    corner handles + a coral FIELD TAG ("Title"/"Subtitle"/"Screenshot"/…).
    A separate fainter DASHED `--accent-soft` box is the HOVER cue.
- `src/App.jsx`:
  - State: `selected {sceneId,field}`, `hoverSel`, `focusField {field,nonce}`.
  - `stageRef` wraps the Player DOM (added `position:relative`); Player now has
    `clickToPlay={false}` (play still works via the dedicated PlayerControls btn).
  - `selectElement({sceneId,field})` resolves scene by id (via `propsRef.current`
    — a fresh-props ref so the long-lived delegated handler never reads a stale
    closure), sets `selected`+`focusField`+`activeIdx`, and seeks ~45% into the
    scene (clamped) so the element is fully revealed when the box lands (NOT the
    bare in_frame where hero reveals are opacity 0).
  - `selectScene(i, {clearElement=true})` — timeline-clip path; now clears the
    element box so the two selection paths agree (clip click highlights clip +
    inspector scene, drops any stale element box).
  - Renders `<SelectionOverlay>` in the canvas; passes `focusField` to EditPanel.
  - Added a discoverability hint ("Click any element to select & edit") + an
    `Icon.cursor` glyph; timeline hint updated.
- `src/EditPanel.jsx`:
  - FIELD_MAP: `title/subtitle/kicker -> text input` (focus+flash),
    `plate/card -> Geometry section` (scroll+flash).
  - On `focusField` change: scrollIntoView the matching control, flash it coral
    (`flashAnchor`), focus the text input. `nonce` re-fires on repeat clicks.
  - Wired `anchorId`/`ref`/`flash` onto the Title/Subtitle/Kicker fields + the
    fallback Title field; `anchorId="sec-geometry"`+`flash` on the Geometry section.
- `src/ui.jsx`: `TextField` is now `forwardRef` and takes `anchorId`/`flash`
  (full-`border` flash to avoid a shorthand/longhand style warning); `Section`
  takes `anchorId`/`flash`. Added `Icon.cursor`.

## data-field -> inspector mapping
| data-field | archetype        | inspector target                    |
|------------|------------------|-------------------------------------|
| title      | hero-title       | Text > Title input (focus + flash)  |
| subtitle   | hero-title       | Text > Subtitle input (focus+flash) |
| kicker     | hero-title       | Text > Kicker input (if present)    |
| plate      | hero-title       | Geometry section (scroll + flash)   |
| card       | apple-screenshot | Geometry section (scroll + flash)   |

scene.id (e.g. "opening-title") is what data-scene-id carries; resolved to the
timeline index via scenes.findIndex(s=>s.id===sceneId).
