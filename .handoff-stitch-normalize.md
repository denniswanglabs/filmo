# Handoff: stitch resolution normalization (stitch crash fix)

## Goal
Fix `adapters.stitch()` crashing (ffmpeg error 234, no final.mp4) when survivor
clips have MIXED resolutions/fps/SAR. Exposed by the real parallel run: after
failure-isolation dropped s2_hero, survivors were 1920x1080 title + 1280x720

## The fix (adapters.py stitch(), concat block only)
Before: fed raw clips to a single `concat` filter with NO normalization.
After: each input is normalized in a `filter_complex` BEFORE concat:
  [i:v:0]scale=W:H:force_original_aspect_ratio=decrease,
         pad=W:H:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=FPS,format=yuv420p[vi]
then [v0][v1]...concat=n=N:v=1:a=0[v].
- Target = project frame spec `W,H,FPS = 1920,1080,30` (module constants, line 36).
- scale-to-fit + pad = letterbox/pillarbox, ASPECT PRESERVED (no distortion).
- setsar=1, uniform fps, yuv420p -> uniform links concat accepts.
- N-input safe; single re-encode pass; VO mux + loudnorm pass below UNCHANGED.
- Signature + return shape identical. diff is stitch-only (verified).

## Why the crash happened (root cause)
Heterogeneous link params (size/fps/SAR/pix_fmt) -> "Input link parameters do not
match" -> ffmpeg rc 234. Normalizing every input to one spec removes the mismatch.
