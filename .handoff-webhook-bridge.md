## The gap that was closed
`stripe_webhook.py:39-44/56-59` decides approve/decline from
`runs/active_budget.json` → `{"budget_cents": N, "spent_cents": M}` against
`amount <= (budget - spent)`. **`orchestrator.py` never wrote that file**, so a live
`stripe listen` would have decided against `{0,0}` and approved everything wrongly.

## How the bridge works (orchestrator.py)
New helper `write_active_budget(runs_dir, budget_cents, spent_cents)` (orchestrator.py,
just below `FREE_TYPES`). Writes `<runs_dir>/active_budget.json` **atomically**
(tmp + `os.replace`) in the exact schema the webhook reads. In a normal run
`runs_dir == HERE/runs`, which is exactly `stripe_webhook.STATE_DEFAULT`'s dir, so the
listener picks it up **with no `--state` flag**. Tests point the webhook at a temp path.

Written at these points so the file always reflects the brain's live verdict numbers:
1. **At budget-lock** (PRICE phase, `set_phase("pricing")`): `{budget, spent=0}` — the
   listener decides against the real ceiling immediately.
2. **Before EVERY `money.authorize()`** (refresh `{budget, spent-so-far}`), at all four
   authorize call sites:
   - approve (was `:282`)
   - downgrade→approve (was `:309`)
   - downgrade→decline (was `:329`) ← over-budget money-shot path
   - plain decline (was `:341`)   ← over-budget money-shot path
   Because the webhook evaluates `charge_amount <= budget - spent`, refreshing `spent`
   to the committed total *before* the authorize means the webhook reproduces the SAME
   verdict the in-process gate just computed. An over-budget cinematic charge
   (`preview > budget - spent`) therefore makes the live webhook return **DECLINE** with
   reason = the brain's verdict (`webhook_declined`), no human in the loop.
3. **Final refresh after the produce loop** so the on-disk state reflects total
   committed scene spend (any post-loop manual authorization capture decides correctly).

Also fixed the stale docstring in `stripe_webhook.py` (it said `runs/<run_id>/budget_state.json`;
the real path it reads is `runs/active_budget.json`, now documented + cross-referenced
to `write_active_budget`).
