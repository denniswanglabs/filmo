# Filmo — web

Next.js 15 (App Router) frontend for Filmo. Paste a URL → the agent reads your
product, plans the cut, prices the job, takes payment, and ships a finished video.
Backend is InsForge; the Railway worker drives the pipeline.

- **Live:** https://filmostudio.vercel.app
- **Stack:** Next.js 15 · React 19 · Tailwind 3.4 · `@insforge/sdk` · `@remotion/player`

## Run locally

```bash
# From anywhere (repo lives under Desktop/Hackathons):
cd ~/Desktop/Projects/Hackathons/walk-studio-hosted/web

npm install
npm run dev        # safe start — always use this (http://localhost:3000)
npm run dev:clean  # nuclear reset — wipes all of .next if dev still breaks
npm run build      # production build (run before deploy)
```

If you're already in the repo root (`walk-studio-hosted/`), `cd web` works too.

**Always use `npm run dev`** (not bare `next dev`). The launcher:
- Kills stale Node/Next listeners on **:3000** and **:3001**
- Clears `.next/cache` every start (prevents stale HMR / webpack chunk errors)
- Auto-deletes a corrupt `.next` when vendor-chunks are missing
- Pins the bundler to `web/` via `next.config.mjs` (ignores stray `~/package-lock.json`)

### If localhost still breaks

| Symptom | Fix |
|---------|-----|
| **Internal Server Error** / `reading 'call'` / vendor-chunks ENOENT | `npm run dev:clean` |
| Page loads on **:3001** but not `:3000` | `npm run dev` — kills both ports |
| Warning about workspace root / multiple lockfiles | Fixed in `next.config.mjs`; restart dev |
| You ran bare `next dev` and things broke | Stop it, then `npm run dev` |

Run dev from **`web/`** only. Avoid `npm run dev:next` unless debugging the launcher itself.

Do not run `npm run build` while the dev server is running — they share `.next` and will corrupt each other.

Env lives in `.env.local` (InsForge URL/keys, demo account, and the developer-mode key).

## For judges — developer mode

Normal visitors get a clean product. **Developer mode** unlocks an inside view of any
build — the machinery behind the magic — without cluttering the consumer UI.

### How to get in

Open the dev link (replace the placeholder with the real key):

```
https://filmostudio.vercel.app/inside?key=YOUR_DEV_KEY
```

What happens:

1. The page captures the `?key=` and strips it from the address bar.
2. A **server action** validates the key against `DEV_MODE_KEY` (server-only — the key
   is never shipped to the browser, returned, or logged).
3. On a match it sets `developer = true` on your signed-in Google account
   (persisted in the `developers` table) — so it sticks **forever for that account**.
4. If you aren't signed in yet, it routes you through Google sign-in first, preserving
   the key, then auto-pairs on return.

You can also just visit `/inside` and paste the key into the form.

### What `/inside/[runId]` shows

Once paired, open the **featured canonical run** (real data, baked in so the demo never
depends on a live build behaving):

```
https://filmostudio.vercel.app/inside/featured-stripe
```

It renders four things:

- **Conversion Read** — the verdict + 6 scored dimensions (promise, outcome, proof,
  show, specificity, CTA) with findings, on-page evidence, and concrete fixes, plus the
  prioritized fixes and the headline that opens the video. (Generated by the real
  free-tier Nemotron over stripe.com.)
- **Priced to profit** — Hermes prices every job to turn a profit (capped at $10) and
  takes payment on Stripe (test mode), no human in the loop. Every run produces and
  every run profits — there are no declines on the live path.
- **NemoClaw containment** — the agent runs **sealed inside NVIDIA NemoClaw** and can
  only pull the five tools we sanctioned. The page **capture + render run host-side via
  those tools** (`CAPTURE_BACKEND` defaults to native/host; in-sandbox capture is
  opt-in) — so "capture" is not claimed to happen inside the sandbox on the live path.
- **P&L** — price, COGS spent, margin, and gross profit.

`/inside/[runId]` also works for **your own runs** (any run id) — non-featured ids are
fetched live from InsForge. Fields a run genuinely doesn't carry are shown as `n/a`.

Non-developers who hit `/inside/[runId]` are bounced to the key-entry page.

### Deploy note (for the operator)

`DEV_MODE_KEY` must be set in the **Vercel project env** (Production) for the hosted
dev link to work — it is server-only and is not committed. The local `.env.local` value
may differ from production and can be rotated freely.
