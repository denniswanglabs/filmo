## Root Causes (Two Distinct, Compounding Bugs)

### Bug 1 (CONFIRMED): `_brand_name()` is wrong for ccTLD URLs

**File**: `plan_job.py`, function `_brand_name()`, line 483–486

**Evidence**:
```
url = 'https://www.tripadvisor.com.tw'
host parts: ['tripadvisor', 'com', 'tw']
name = host[-2]  →  'com'  →  'Com'
```

For `tripadvisor.com.tw` (Taiwan ccTLD), the part at index `[-2]` is `"com"` (the second-level domain segment), not the actual brand name `"tripadvisor"`. This is why the real prod runs (`build-com-f8a8eb`, `build-com-2dab35`) generate a plan using the brand name **"Com"**: voiceover beats say "Com.", "Com helps you do more with less.", "Get started with Com today." — all completely wrong. The kicker on the explainer cards renders "TRIPADVISOR" (from `brand_theme.json`'s correctly-resolved `name` field), which contradicts the title text.

**Proposed fix** (`plan_job.py:483–486`):
```python
def _brand_name(url):
    u = (url or "").lower().replace("https://", "").replace("http://", "").replace("www.", "")
    host = u.split("/")[0].split(".")
    # Skip known ccTLDs so 'tripadvisor.com.tw' -> 'tripadvisor', not 'com'
    _KNOWN_CCTLD_SLDS = {"com", "co", "org", "net", "edu", "gov"}
    if len(host) >= 3 and host[-2].lower() in _KNOWN_CCTLD_SLDS:
        # e.g. ['tripadvisor', 'com', 'tw'] -> 'tripadvisor'
        name = host[-3]
    elif len(host) >= 2:
        name = host[-2]
    else:
        name = host[0] if host else "the product"
    return name.capitalize()
```

### Bug 2 (CONFIRMED): `brand_extract.py` bot-blocked by Tripadvisor → `features: []` → bullets always empty

**File**: `brand_extract.py`, function `_live_webfetch()` (lines 393–418) / `_parse_html_brand()` (lines 330–390)

**Evidence** (from `brand_theme.json` in both real and mock runs):
```json
{
  "features": [],
  "tagline": ""
}
```

Both fields are empty for every tripadvisor.com.tw run. Tripadvisor bot-blocks generic UA requests (their Akamai WAF returns a bot-challenge page with no parseable `<h2>/<h3>` or `<nav>/<li>` content, so `_parse_html_brand()` returns `features: []`). The `except Exception: return ""` in `_live_webfetch()` gracefully degrades exactly as designed — but the result is a brand with NO features.

**Downstream effect**: In `style_fill.py`, `_shape_explainer()` (lines 241–299) builds bullet list from `brand["features"]`. When features is `[]`, bullets resolves to `[]`. The `explainer-card` archetype renders just a single truncated title line with nothing below it — visually sparse but technically not "blank". The ExplainerCard template does render the kicker + title + underline, which is why the frames are NOT fully blank. But the lower two-thirds of each feature scene is empty whitespace.

### Bug 3 (SECONDARY): Title truncation at 48-char limit produces dangling half-sentences and trailing commas

**File**: `style_fill.py`, function `_title_from_text()`, line 200–209 (`limit=48`)

**Evidence**:
```
"Tripadvisor provides trusted hotel reviews from"  ← ends with "from"
"Tripadvisor offers authentic restaurant ratings"   ← cuts mid-thought
"Tripadvisor lets you explore activities, tours,"   ← trailing comma
"Start planning your next trip today at"            ← missing the URL
```

The 48-char limit is appropriate for a short punchy headline, but the voiceover text is full sentences (80-120 chars). The shaper takes the WHOLE first sentence up to a period, then clips to 48 chars on a word boundary. The result is grammatically broken half-sentences shown as display headlines.

**Proposed fix option A** (raise limit for explainer-card):  
In `_shape_explainer()` line 255, change:
```python
or _title_from_text(d.get("_text") or "")
```
to pass a higher limit:
```python
or _title_from_text(d.get("_text") or "", limit=72)
```

**Proposed fix option B** (pass the full VO sentence to the card's title, not clipped — let the React component wrap it):  
Set data.title to the full `d.get("_text")` directly (the ExplainerCard already wraps) rather than going through `_title_from_text()` at all.

## Why the "verify" run is different from the "real" runs

- **verify run**: The plan was written manually (or by Nemotron with correct brand facts), so it uses "Tripadvisor" as the brand name in the VO beats (e.g., "Tripadvisor provides trusted hotel reviews from…"). The plan.json voiceover beats carry full sentences, which then get truncated to 48 chars by `_title_from_text()` → dangling titles, empty bullets.
- **real runs** (build-com-*, build-com-2dab35): The plan was generated by `_template_plan()` which called `_brand_name("https://www.tripadvisor.com.tw")` → "Com". Nemotron was either unavailable or not set, so it fell back to the deterministic template. The voiceover beats say "Com." and "Com helps you do more with less." — completely wrong brand.

## Priority Order for Fixes

1. **HIGHEST**: `plan_job.py:_brand_name()` — ccTLD parsing bug. This corrupts the ENTIRE plan's brand identity for any `.com.tw`, `.co.uk`, `.co.jp`, etc. URL.  
2. **HIGH**: `brand_extract.py` bot-block path — no actionable fix without changing the fetcher (maybe a Playwright-based fetch or a fallback via Google), but the current `features: []` graceful degradation means the content is sparse not broken. Could add a `features` fallback to the template plan's VO beat nouns when `brand.features` is empty.  
3. **MEDIUM**: `style_fill.py:_title_from_text()` limit — raise from 48 to 72 chars for explainer-card context, or use full VO sentence as title (the React card wraps text).
