# Handoff: MOCK walkthrough == STANDARD paid walkthrough (real walk_native, $0)

Date: 2026-06-23
Scope: Walk Studio pipeline only. Edited `adapters.py`, `orchestrator.py`, `build_runner.py`.
Did NOT touch `dashboard/`, `studio/`, `walk_native.py` internals, or external walk-ultra.
Builds on `.handoff-wtfallback.md` (placeholder bool + accent_hex + real-mode placeholder-drop gate).

Backups: `adapters.py.pre-mockstd.bak`, `orchestrator.py.pre-mockstd.bak`.
(build_runner.py was a tiny additive change — no separate backup needed; revert from git/diff.)

## Goal
Make a $0 MOCK build produce the SAME walkthrough a paying STANDARD customer gets.
Before: mock swapped in a SYNTH placeholder card; only real mode ran the genuine
`walk_native` capture. Now mock runs the REAL `walk_native` capture too. Mock and real
differ ONLY in payment (mock keeps `PRODUCER_SIMULATE_PAID`; real opens the Stripe gate)
and brain ($0 super-free). Screenshots already ran real (Playwright) in mock — unchanged.

## What changed

### 1. `adapters.generate_walkthrough()` — mock now takes the native capture path
- Added a NATIVE-CAPTURE DECISION after the cache block:
  `native_walkthrough = (mode == "real") or bool(env WS_WALKTHROUGH_NATIVE)`.
- When `native_walkthrough` is True (real mode ALWAYS; mock when the flag is set) the
  function runs the genuine `walk_native.py` Playwright capture — the SAME code real
  mode always used. Genuine capture returns `{real:True, native:True, placeholder:False}`.
- When `native_walkthrough` is False (mock with NO flag) it emits the brand-accent SYNTH
  card (`placeholder:True, synth_color=<accent>`) — the fast/offline path the unit-test
  suite needs (those tests call `orchestrate` directly and never set the flag).
- The synth card is now a LAST-RESORT FALLBACK: new inner `_walkthrough_fallback()`
  returns the synth card in MOCK and `None` in REAL. Every native-failure exit
  (`no venv/script`, `TimeoutExpired`, `rc!=0 / too-small mp4`) now returns
  `_walkthrough_fallback()` instead of bare `None`. In real mode that's still `None`
  (byte-identical to before); in flagged-mock it's a synth placeholder the gate drops.
- `WS_WALKTHROUGH_CACHE` override is UNCHANGED and still first (proven `placeholder:False`
  reuse, mode-independent).

### 2. `build_runner.run()` — flags real product builds to want a native walkthrough
- Sets `os.environ["WS_WALKTHROUGH_NATIVE"] = "1"` (next to HERMES_BRAIN/HERMES_STYLE).
- Every dashboard/product build (mock OR real) goes through `build_runner.run`, so every
  real product mock build now gets the genuine walk_native walkthrough.
- Unit tests drive `orchestrate` DIRECTLY (verified: the only test through `build_runner.run`,
  `test_build_runner_failure`, stubs `orchestrate` to raise — never reaches the walkthrough),
  so the flag is absent in tests and they keep the deterministic synth path. Suite stays
  $0/offline as `run_all_tests.sh` documents.

### 3. `orchestrator.py` placeholder-drop gate — now fires in MOCK too
- Old gate: `if mode == "real" and info.get("placeholder")`.
- New gate: `intended_real_walkthrough = (mode=="real") or bool(env WS_WALKTHROUGH_NATIVE)`;
  drop when `intended_real_walkthrough and info.get("placeholder")`.
- So a failed/last-resort-placeholder walkthrough drops its scene + VO beat in real AND in
  every real product mock build — mock now behaves like standard. VO beat drops
  automatically (it's keyed off produced clips; see `.handoff-wtfallback.md`).
- Offline test mock (no flag): gate is False -> mock synth placeholder KEPT, so the
  orchestrator-judgment tests still ship the mock walkthrough unchanged.
- Also REMOVED the `_walkthrough_gen` short-circuit `if not cache and studio_active and
  mode=="mock": return studio_placeholder(...)`. The dashboard build runs with
  `overlays="studio"` (studio_active True), so that line USED to force a studio placeholder
  for every mock dashboard build — it was the thing blocking the real capture. Now mock
  goes straight to `generate_walkthrough` (native). `studio_placeholder` is still used by
  the CINEMATIC slot (lines ~607/649) — untouched.

## Mock-vs-real diff after the change (the requested reasoning)
They now differ ONLY in:
  - PAYMENT: mock keeps the simulated paid gate (`PRODUCER_SIMULATE_PAID`); real opens the
    Stripe gate. (Untouched — handled in `build_runner._payment_gate`, not in this change.)
  - BRAIN: default `super-free` ($0). (Untouched.)
The WALKTHROUGH ASSET is now IDENTICAL: both run `walk_native` (`placeholder:False`,
kept) on success; both DROP scene+VO on failure (real -> None; flagged-mock -> synth
placeholder, gate drops). Screenshots were already real in both modes.

REAL MODE IS BYTE-UNCHANGED: for `mode=="real"`, `native_walkthrough` is always True so the
synth block is skipped; the native-capture subprocess + success dict are identical to the
backup; every failure path returns `_walkthrough_fallback()` which returns `None` for real
(== backup's `return None`). Confirmed by `diff` of the function body (only comments +
the no-op-for-real fallback indirection differ).
