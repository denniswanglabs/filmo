# Handoff: ccTLD brand-name fix

**Date:** 2026-06-21
**Status:** COMPLETE

## Problem
For ccTLD domains like `tripadvisor.com.tw`, `_brand_name()` in `plan_job.py` parsed
host parts `['tripadvisor','com','tw']` and returned `host[-2]` = "Com". This corrupted
the template plan VO for any `.com.tw`, `.co.uk`, `.co.jp`, `.com.au`, etc. site.

## Approach taken
**Approach A (preferred)** — reuse the already-correct brand name from `company_facts`.

`brand_extract.py` is already public-suffix-aware and correctly returns `"Tripadvisor"`
in `brand_theme.json["name"]`. This name flows into `plan_job()` via the `company_facts`
dict (key: `"wordmark"`), which was already in scope but not threaded to `_template_plan`.

## Changes made
**File:** `plan_job.py` only (no other files touched)

1. In `plan_job()`: added `_resolved_brand` computed from `company_facts["wordmark"]`
   when non-empty, falling back to `_brand_name(url)` when company_facts is absent.
2. All three `_template_plan(...)` call sites inside `plan_job()` now pass
   `brand=_resolved_brand`.
3. `_template_plan()` signature changed from `(... quality="standard")` to
   `(... quality="standard", brand=None)` — `brand = brand or _brand_name(company_url)`.
   Backward-compatible: standalone `_template_plan()` calls (e.g. from `__main__`)
   still work correctly via URL-parse fallback.

## Verification output

## What was NOT changed
- `brand_extract.py` (already correct)
- `build_runner.py` (no change needed; it already passes `company_facts`)
- `style_fill.py`, `build_timeline.py` (out of scope)
- No server/dashboard files touched
