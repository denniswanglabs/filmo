## Problem (from R2 finding)
Terse fetchable brands (Linear, Plaid) scored D3=2: the VO opened with a BARE
WORDMARK beat ("Linear." / "Plaid.") + generic SaaS lines, no named features, no
numbers. Root cause: world-knowledge enrichment fired ONLY on an EMPTY scrape; a
THIN-but-present scrape skipped it, and the LLM/template emitted a single-word beat.

## Fixes landed
1. **Ban single-word / bare-wordmark beats** — three layers:
   - `validate_planner.SYSTEM_PROMPT` VOICEOVER RULES: new "NO BARE-WORDMARK /
     SINGLE-WORD BEATS" rule + added bare wordmark to BANNED FILLER.
   - `plan_job._QUALITY_PROMPT["standard"]`: "THE OPENING BEAT IS LOAD-BEARING" —
     must be a full value-prop naming a feature/metric, never "Linear."/"Plaid.".
   - **Deterministic post-processor** `_degut_bare_wordmark_beats()` runs on the
     FINAL plan (LLM OR template) in `plan_job()` after `_restyle_durations`:
     `_is_bare_wordmark_beat()` flags <=1-word or brand-only beats; rewrites them to a
     grounded value-prop (world-knowledge first, then scraped features).
2. **Fire enrichment on THIN, not just EMPTY scrapes** — `company_facts_block()` now
   detects thin scrapes (`_is_thin`: <3 features OR avg <3 words) and appends the
   world-knowledge ENRICH instruction ON TOP of the scraped facts (with named example
   features for stripe/linear/plaid). Previously the `if features:` branch skipped it.
3. **Seeded `_BRAND_WORLD_KNOWLEDGE`** — restructured each entry from a 4-tuple to a
   5-tuple adding an `open_line` (full value-prop). Enriched linear (Cycles, Projects,
   Triage, sub-second, keyboard-first) and plaid (Link, Auth, Balance, Signal, 12,000+
   banks). `_grounded_template_beats` + `_standard_template_plan` updated to use it for
   the `title-open` beat instead of `"%s." % brand`.
4. Kept R2 wins: never-invent-a-different-business guard, no hollow filler, no
   "use the [gerund]" bug, imperative couplets, grounded offline template.
