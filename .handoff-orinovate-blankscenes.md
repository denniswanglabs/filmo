## ONE-LINE ROOT CAUSE

The dashboard build path (`build_runner.py → orchestrator.orchestrate → per-scene clips → ffmpeg concat`) NEVER touches the new VO-driven `<Timeline>` engine (`align_vo → build_timeline → style_fill → studio <Timeline>`). In that legacy path, a `cinematic` scene with no Higgsfield spend (any `mode="real"` $0 run, OR any non-studio-mock run) degrades to a **flat solid-color `synth_clip`** — so the 18s of cinematic scenes rendered as a single solid amber frame (`0xB45309`) while the VO kept narrating. The never-blank fallback that the good `style-fill-sample` relied on lives only in the unused engine.

## WHY IT BLANKED (code path trace)

1. `build_runner.build_and_produce()` calls `orchestrator.orchestrate(plan, run_id, mode=mode, overlays=("studio" if mode=="mock" else "mock"), earn=earn)` (build_runner.py ~line 137).
   - This run had ledger `mode: "real"` → `overlays="mock"`.
2. `orchestrator.py` line 187: `studio_active = (overlays == "studio" and mode == "mock")` → **False** for this run. (Confirmed: every ledger scene has `studio: null`.)
3. Cinematic scenes, standard quality, hit the branch at orchestrator.py **lines 458–466**:
   ```python
   if premium and not quality_premium:        # standard cinematic
       if studio_active:
           studio_block = adapters.studio_overlay(scene, out, palette)   # designed card
       else:
           adapters.generate_overlay(dict(scene, type="motion_graphic"), out, mode, ...)  # <-- TAKEN
   ```
   With `studio_active=False`, it calls `generate_overlay(..., type="motion_graphic", mode=...)`.
4. `adapters.generate_overlay()` (adapters.py 814–846): in mock it `synth_clip(TYPE_COLOR["motion_graphic"]="B45309")`; in the real branch it shells `remotion render Overlay` and on ANY failure/missing-kit **falls back to** `synth_clip(TYPE_COLOR["motion_graphic"])` (lines 843–845). Either way the output is the flat amber `0xB45309` we see. No VO text, no brand, no motion.
5. `synth_clip()` (adapters.py 88–93) = `ffmpeg -f lavfi -i color=c=0xB45309 ...` — a literal solid color card. **This is the blank scene.**

So the legacy per-scene path has NO "design an explainer card from the VO" behavior for a cinematic scene that gets no real video — it emits a labelled color card and ships it.

### The fill mechanism that SHOULD have caught it — and why it didn't fire
The new engine already guarantees never-blank, but is NOT wired into the build path:
- `style_fill.Style.archetype_for()` (style_fill.py 151–152): unmatched role → `default_archetype` (= `ARCH_HERO`, "hero-title"). Every scene resolves to a real archetype.
- `studio/src/timeline/Timeline.tsx` `SceneBody` (lines 27–44): switch on `archetype` with a **default tail `return <HeroTitle .../>`** — there is no placeholder/blank branch. Any scene, matched or not, renders a real React archetype filling its full `in_frame→out_frame` span.
- `style-fill-sample` (the proven-good output) used exactly this: `timeline.json`/`props.json` present, all scenes resolved to `hero-title`/`card-ui`, light Orinovate theme.
- The Orinovate run d97898 has **NO `timeline.json` and NO `props.json`** → it never ran `align_vo.py`/`build_timeline.py`/`style_fill.py`. `grep` confirms `build_runner.py` and `orchestrator.py` never import or call `style_fill`, `build_timeline`, or `align_vo`. The engine is dead code on the dashboard path.

So: **a never-blank fallback archetype DOES exist (HeroTitle default in Timeline.tsx + default_archetype in style_fill), but the Orinovate run bypassed the entire engine that uses it.**

## EXISTING ARCHETYPE INVENTORY

New VO-driven engine — `studio/src/timeline/archetypes/`:
- `HeroTitle.tsx` — kicker / title (with punch-word accent split) / subtitle. **This is the default/fallback** (Timeline.tsx tail + style_fill `default_archetype=ARCH_HERO`).
- `CardUi.tsx` — heading + 4 capability cards.
- `AppleHero.tsx`, `AppleRegistry.tsx`, `AppleStatement.tsx` — Apple-style set (registered in Timeline.tsx, used by an Apple style).
- Timeline routing keys: `card-ui`, `apple-hero`, `apple-registry`, `apple-statement`, else→`hero-title`.
- `style_fill.STYLES["orinovate-kinetic-light"]`: role_map open/close/cta/title→hero-title, feature/capability/grid→card-ui, `default_archetype=hero-title`, `theme_fn=_theme_kinetic_light` (correct light/navy/blue).

Legacy per-scene templates — `remotion_codegen.py`: `_CENTERED`, `_EDITORIAL`, `_DIVIDER` (title/motion_graphic), `_PLACEHOLDER` (cinematic/walkthrough storyboard, scan-line). NOTE: even `_PLACEHOLDER` renders real animated content — it is NOT the blank. The blank comes strictly from `synth_clip`/`generate_overlay` fallback, which only fire when `studio_active=False`.

Gap: there is NO archetype in the new engine that maps a `cinematic` plan role to a designed VO-explainer card. With the engine wired in, cinematic would fall to `default_archetype=hero-title` (acceptable, never-blank), but a richer dedicated explainer archetype would be better for a "narrate the factory floor / dashboard" beat.

## FIX SPEC (prioritized; implement-ready, NOT implemented here)

### FIX 1 (PRIMARY — eliminates blanks): wire the dashboard build onto the VO-driven `<Timeline>` engine
The clean, durable fix. Route production through the engine that already never blanks.
- **File:** `build_runner.py` (the `orchestrator.orchestrate(...)` call ~line 137) and/or `orchestrator.py` produce/stitch section (lines ~359–765).
- **Change:** after the plan + VO are decided, run the engine instead of (or after) per-scene clip production:
  1. `align_vo.py` → `vo_alignment.json` (cue frames per scene from the VO).
  2. `build_timeline.py` → `timeline.json` (in/out frames + cues; scene ids match plan).
  3. `style_fill.build_props(timeline, plan, brand, style_name="orinovate-kinetic-light")` → `props.json`, then `_stage_audio`.
  4. Render `studio` composition `Timeline` with `--props=props.json` to `final.mp4` (mirror `studio/render-timeline-smoke.sh`).
- **Brand:** pass a real brand object from `brand_extract.py` so `_theme_kinetic_light` produces the light/navy/blue Orinovate theme (fixes FIX 3 for free). Do NOT use `remotion_codegen.palette_for`, which returns `_brand="generic"`.
- **Result:** cinematic/any-unmatched scene → `default_archetype=hero-title` (or the new explainer archetype from FIX 2), VO-driven, full-span, never blank.
- **Style selection** must be chosen per brand; `style_fill.STYLES` currently only has `orinovate-kinetic-light`. Generalize the registry key or default to it for now.

### FIX 2 (the requested default explainer archetype): add `ExplainerCard` for cinematic / unmatched roles
So a "no cinematic footage" beat SHOWS the narrated point as on-brand motion-graphics rather than just repeating a hero title.
- **New file:** `studio/src/timeline/archetypes/ExplainerCard.tsx` — a kinetic explainer card consuming `data` = `{ kicker, title, subtitle, bullets?[] }`, themed from `theme` (light bg `#ffffff`, navy `#1a3a5c` sidebar/heading, blue `#2563eb` accent — match `style-fill-sample/props.json`). Full-span animation: word-rise title on the scene's first cue, staggered bullet reveals on subsequent cues, a subtle navy left rail + blue underline (Orinovate sidebar motif). On-brand for Taiwan 3D-print/CNC: bullets default to capability nouns parsed from the VO/brief. NO emojis (numbered/letter badges or SVG icons only).
- **Register in:** `studio/src/timeline/Timeline.tsx` `SceneBody` — add `if (scene.archetype === "explainer-card") return <ExplainerCard .../>;` before the default tail. Add the import at top.
- **Type:** add `"explainer-card"` to `studio/src/timeline/types.ts` `Archetype` union.
- **Register in:** `style_fill.py` — add `ARCH_EXPLAINER = "explainer-card"`; add a `_shape_explainer(scene, brand)` shaper (kicker/title/subtitle/bullets from plan copy → brand fallback); in `STYLES["orinovate-kinetic-light"]` map `"cinematic": ARCH_EXPLAINER, "walkthrough": ARCH_EXPLAINER, "demo": ARCH_EXPLAINER`, add `ARCH_EXPLAINER: _shape_explainer` to `shapers`. (Keep `default_archetype` as a safe never-blank floor; explainer is now the explicit cinematic mapping.)
- **Net:** the never-blank guarantee is enforced at TWO layers — `style_fill.archetype_for` always returns a known archetype, and `Timeline.tsx` always returns a component (default `HeroTitle`). No scene can resolve to nothing.

### FIX 3 (theme correctness): resolve the real Orinovate brand, not the generic fallback
Even with FIX 1+2, confirm the brand object is the curated light theme.
- **Root:** `remotion_codegen.palette_for('orinovate.com')` returns `_brand="generic"` / dark+mint. Source the brand from `brand_extract.py` (which produced the correct `style-fill-sample` theme: bg `#ffffff`, navy `#1a3a5c`, accent `#2563eb`, wordmark "Orinovate") and feed it to `style_fill._theme_kinetic_light` via `build_props`.
- If keeping any legacy path, fix `palette_for` so a known brand resolves its curated palette instead of generic.

### LOWER PRIORITY: legacy-path safety net (only if FIX 1 is deferred)
If the legacy per-scene path must keep shipping near-term, make a cinematic scene with no real media render a designed card instead of `synth_clip`:
- **File/func:** `orchestrator.py` lines 462–466 (and 510–513, 549–553) — when `studio_active` is False, route cinematic/walkthrough through `adapters.studio_overlay` (designed card) anyway, OR have `adapters.generate_overlay`'s fallback (adapters.py 817/823/844) call a real designed-card renderer rather than `synth_clip(TYPE_COLOR[...])`. This is a patch, not the real fix; FIX 1 is preferred.

## VERIFICATION RECIPE (re-render Orinovate $0/mock, assert zero blank frames in any VO span)

1. Re-run the build at $0:
   - `python build_runner.py --url https://www.orinovate.com --mode mock --simulate ...` (use the existing mock/$0 flags; `mode=mock` also makes `studio_active=True` if staying on legacy, but the goal is FIX 1's engine path).
2. Extract 1fps stills (note: macOS has no `timeout` — bound with `perl -e 'alarm N; exec @ARGV'`):
   ```
   cd runs/<new-run>/ && mkdir -p _diag-stills
   perl -e 'alarm 90; exec @ARGV' ffmpeg -y -i final.mp4 -vf fps=1 _diag-stills/f%03d.png
   ```
3. Assert NO solid/near-black/single-color frame inside any VO span. Per-scene flat-frame check:
   ```
   # YAVG should NOT be constant across a scene, AND a 1x1 downscale must not be a known placeholder color.
   ffprobe -v error -f lavfi "movie=final.mp4,signalstats" -show_entries frame_tags=lavfi.signalstats.YAVG -of csv
   # Flag any clip whose 1x1 avg == B45309 / 1F3A8A / 0F766E / 0A0D0C / 3A0D0D (TYPE_COLOR placeholders):
   for f in clips/*.mp4; do ffmpeg -v error -ss 1 -i "$f" -frames:v 1 -vf scale=1:1 -f rawvideo -pix_fmt rgb24 - | xxd; done
   ```
   PASS = no clip is a TYPE_COLOR solid; every scene shows varying content within its span.
4. Stronger automated gate: for each scene span, sample N frames, compute per-frame color variance (stddev of pixels). Assert stddev > threshold (a real card with text/motion has high spatial variance; a solid color ~0). Fail the build if any VO-covered span is below threshold.
5. Visual spot-check: read `_diag-stills/f005.png`, `f009.png`, `f015.png` (the previously-blank 5–18s window) — they must now show Orinovate-themed explainer content (light bg, navy/blue), not solid amber.
6. Confirm theme: stills show light/white bg + navy + blue accent (NOT dark + mint-green), wordmark "Orinovate".
