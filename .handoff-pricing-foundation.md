## TL;DR
A tiered + a-la-carte premium pricing menu. ALL new behavior is gated behind env
`WS_PREMIUM_MENU=1` (default OFF -> existing estimate/price/gate byte-identical,
proven against captured baselines). The budget gate + Stripe authorize logic are
UNTOUCHED — only the budget/price NUMBERS fed into them change. Money is integer
CENTS (USD), matching producer.py.

## Files
- `pricing.json`   — SINGLE source of truth for all numbers (tiers + boosters).
- `pricing.py`     — loader/API: `load_pricing()`, `price_selection()`, `validate_consent()`, `default_selection()`.
- `plan_schema.py` — adds optional `selection` top-level key + `validate_selection()`; plans WITHOUT `selection` still validate.
- `producer.py`    — `cmd_estimate()` reads the menu ONLY when `WS_PREMIUM_MENU=1`.
- `tests/test_pricing.py` — 18 tests, wired into `run_all_tests.sh` (section 2b).
- Backups: `producer.py.pre-premium.bak`, `plan_schema.py.pre-premium.bak`.

## The FLAG
`WS_PREMIUM_MENU` truthy = `1`/`true`/`yes`/`on` (case-insensitive). Anything else =
OFF. OFF path is byte-identical to the pre-change `cmd_estimate` (verified via diff).

## CONTRACT 2 — the `selection` object (shared by plan_schema + dashboard)

```json
{
  "tier": "starter | pro | studio",
  "boosters": ["rush", "founder_voice", "multi_format", "no_watermark",
               "extra_language", "extra_revision"],
  "options": {
    "languages": 0,
    "revisions": 0,
    "formats": 0,
    "consent": { "attested": false, "owner": "" }
  }
}
```
- `boosters` must be UNIQUE (no repeats — quantities live in `options`).
- `options.languages|revisions|formats` = number of EXTRA units (>= 0; per-unit
  boosters need their field >= 1).
- Default selection (`pricing.default_selection()` / `plan_schema.default_selection()`):
  starter, no boosters, all options 0, consent {attested:false, owner:""}.
- A plan may carry `selection` as an optional FOURTH top-level key
  (`job/scenes/voiceover/selection`). Plans WITHOUT it still validate.

## CONTRACT 3 — `price_selection(selection)` output

```json
{
  "tier": "studio",
  "line_items": [
    {"key": "tier", "label": "Studio tier", "qty": 1,
     "unit_price_cents": 24900, "unit_cogs_cents": 6000,
     "price_cents": 24900, "cogs_cents": 6000},
    {"key": "rush", "label": "Rush delivery", "qty": 1,
     "unit_price_cents": 5000, "unit_cogs_cents": 0,
     "price_cents": 5000, "cogs_cents": 0}
    // ...one per selected booster...
  ],
  "total_price_cents": 43400,
  "total_cogs_cents": 8500,
  "margin": 0.804147...
}
```
- `price_cents = unit_price_cents * qty`; `cogs_cents = unit_cogs_cents * qty`.
- `margin = (total_price - total_cogs) / total_price` (0.0 when total_price == 0).
- Raises `pricing.PricingError` on unknown tier / unknown booster / ineligible
  booster / bad per-unit qty / duplicate boosters.
- Raises `pricing.ConsentRefused` (subclass of PricingError) when the consent
  guardrail refuses (see Contract 5). Consent is checked BEFORE pricing.

### STABLE line-item LABELS (match on these if you must)
| key            | label                  |
|----------------|------------------------|
| tier=starter   | `Starter tier`         |
| tier=pro       | `Pro tier`             |
| tier=studio    | `Studio tier`          |
| rush           | `Rush delivery`        |
| founder_voice  | `Founder voice clone`  |
| multi_format   | `Multi-format cut`     |
| no_watermark   | `Watermark removal`    |
| extra_language | `Extra language`       |
| extra_revision | `Extra revision round` |
Per-unit qty is in `qty` (e.g. Multi-format cut qty=2), not duplicated rows.

## CONTRACT 4 — producer.py integration (the budget/price the gate sees)

`producer.cmd_estimate(plan)` adds these keys ONLY when `WS_PREMIUM_MENU=1`:
- `pricing_mode`: `"premium_menu"`
- `selection`: the resolved selection (plan's, or `default_selection()` if absent)
- `menu`: the full `price_selection()` output (Contract 3)
- `menu_total_cogs_cents`: == menu COGS
- **OVERRIDES** (the load-bearing change):

UNCHANGED in both modes: `scenes[]` per-scene `est_cost_cents` report, `voiceover`
line, `total_cogs_cents` (legacy per-scene rollup — note this is the per-scene COGS,
NOT the menu COGS; read `production_budget_cents` / `menu_total_cogs_cents` for the
locked ceiling on the premium path). The `gate` subcommand and Stripe authorize are
NOT touched — the orchestrator already passes the locked `budget_cents` into
`cmd_gate`, so the gate just receives the menu-derived ceiling. Per-scene gate
reasoning (approve/downgrade/decline) is identical logic.

## CONTRACT 5 — consent rules + refusal reasons

`pricing.validate_consent(selection) -> (ok: bool, reason: str)`. Enforced inside
`price_selection` (raises `ConsentRefused` when ok is False). Applies to any booster
with `consent_required:true` in pricing.json (today: `founder_voice`).

REFUSE (ok=False) when founder_voice is selected and ANY of:
1. `options.consent.attested != true`
   -> `"founder_voice requires an explicit consent attestation (options.consent.attested must be true)"`
2. `options.consent.owner` empty/blank
   -> `"founder_voice requires a named first-party voice owner (options.consent.owner must be non-empty)"`
3. owner reads as a public figure / third party (refusal heuristic)
   -> `"refusing to clone a voice that is not the consenting first party: <why>"`
   where `<why>` is one of:
     - `named owner '<x>' matches a known public figure` (denylist)
     - `named owner '<x>' reads as a third party / public figure` (marker words:
       friend, celebrity, president, ceo of, actor, influencer, impersonat..., etc.)
     - `named owner '<x>' is a generic placeholder, not a first-party identity`
       (n/a, none, anonymous, test, someone, owner, founder, ...)

ALLOW (ok=True): `"consent attested by '<owner>'"` for an attested, named,
first-party owner. NEVER allow an unconsented or third-party clone. The heuristic is
deliberately conservative (when in doubt -> refuse); it is a guardrail, not identity
verification. Extend `_PUBLIC_FIGURE_DENYLIST` / `_THIRD_PARTY_MARKERS` in pricing.py.

NOTE on eligibility-vs-consent ORDER: `price_selection` checks tier eligibility
during the line-item loop, but calls `validate_consent` FIRST. So `founder_voice` on
`starter` raises `ConsentRefused` if consent is also missing — but with valid consent
it raises the eligibility `PricingError` ("booster 'founder_voice' not eligible on
tier 'starter'"). Either way it is REFUSED; check `isinstance(e, PricingError)` to
catch both.
