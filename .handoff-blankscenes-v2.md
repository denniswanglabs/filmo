# Handoff — blank-scenes v2 (content-empty fix)

## Root cause (confirmed)
The earlier fix killed the amber flat-color blank but left a CONTENT-empty blank:
feature beats rendered as empty hero-titles (bare glow, no text).

Two threading gaps:
1. `build_timeline.py` copied `scene.get("archetype")` (always None for plan
   scenes — they carry `type`, not `archetype`) and NEVER carried role or text.
   Result: timeline.json had `archetype=None`, no role, no text.
2. `style_fill.py` re-derived archetype from the raw plan scene. `_scene_role`
   returned `"motion_graphic"` for feature beats, but `role_map` had NO
   `motion_graphic` key -> fell to `default_archetype=hero-title`. ALL 5 scenes
   became hero-title. The hero shaper read `scene["data"]` (plan scenes have
   `brief`, not `data`) -> fell to brand tagline; feature beats showed an
   identical/empty hero instead of their narrated point.

## Changes (Phase 1 — code)
### build_timeline.py
- Added `_TYPE_TO_ROLE` + `_ID_ROLE_HINTS` + `_derive_role(scene)`:
  plan `type`/`id` -> a semantic role (motion_graphic -> "feature"; title ->
  "title"; cinematic/walkthrough/demo passthrough). NEVER None.
- Added `_beat_text` + `_derive_text(scene, alignment, brand_fallback)`:
  scene text sourced VO beat -> brief -> data.title -> brand fallback. NEVER "".
- `build_timeline(...)` now takes `brand_fallback` and emits `role` + `text`
  on every scene.
- CLI: added `--brand-fallback`.

### style_fill.py
- `run_pipeline` computes `brand_fallback` (tagline/wordmark) and passes it to
  `build_timeline.build_timeline`.
- role_map: `feature`/`motion_graphic`/`motion-graphic` -> `explainer-card`
  (was: feature -> card-ui). Brand-grid roles (capability/cards/grid) stay
  card-ui.
- `build_props`: prefer the timeline scene's threaded `role` (sets
  plan_scene["role"] so archetype_for agrees) and threaded `text` (seeded into
  data["_text"]).
- `_brand_fallback_title(brand)` helper (tagline -> wordmark -> name).
- `_shape_hero` + `_shape_explainer`: title source now explicit copy ->
  threaded `_text` -> brief -> brand fallback. NEVER empty. Explainer subtitle
  no longer echoes the title.

### studio archetypes (never-empty guards)
- ExplainerCard.tsx: `titleText = data.title.trim() || theme.wordmark`;
  subtitle uses guarded `subText`. Renders fallback wordmark, never bare glow.
- HeroTitle.tsx: `titleText = data.title.trim() || theme.wordmark`; separate
  wordmark line hidden when it would duplicate the fallback title.

## Phase 1b — short-scene fallback (HeroTitle.tsx)
First render showed the hero title NEVER appearing on the 31-frame `title-open`
scene: the hard-coded `title-in` fallback was 36 frames > the 31-frame scene, so
only wordmark+kicker showed. Fixed: hero fallback cue frames now scale to
`durationInFrames` (titleFallback = min(36, round(dur*0.22)); kicker/punch/sub
scale similarly) so the title + subtitle always land inside short scenes.
