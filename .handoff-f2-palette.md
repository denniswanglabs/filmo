# Handoff: F2 — Brand Palette Fix

**Date:** 2026-06-22
**Status:** COMPLETE — all tests green, verified 5-brand table

## What was done

Edited `brand_extract.py` ONLY (no other files touched).

### Changes

1. **`_WELL_KNOWN_ACCENTS` dict** (new, ~35 brands): maps lowercase registrable brand
   labels to curated real-world accent hex values. Used ONLY for unknown/thin-data
   brands as a world-knowledge fallback. Brands already in `remotion_codegen.BRAND_PALETTES`
   are NOT double-entered — the curated path handles them unchanged.

2. **`_hex_luminance(hex_color) -> int`** (new helper): ITU-R BT.601 luma
   approximation (0-255). Fast, no floats.

3. **`_is_valid_accent(hex_color) -> bool`** (new helper): returns True only for
   hex colors with 15 ≤ luma ≤ 240. Rejects near-white (>240) and near-black (<15)
   structural/background colors that are never valid accents.

4. **Post-assembly accent quality guard in `extract_brand()`** (new block, unknown brands only):
   After the theme is assembled (incl. any fetch-derived accent), if the current
   accent fails `_is_valid_accent()` (e.g. `#FFFFFF` from Plaid's theme-color),
   replace it with: world-knowledge lookup → else `_LIGHT_DEFAULT` blue.
   If the accent is valid but still the generic `_LIGHT_DEFAULT` blue (`#2563EB`),
   check world-knowledge and upgrade if known.

### What was NOT changed

- `remotion_codegen.py` — untouched
- Any prompt/capture/render file — untouched
- The known-brand path (Stripe, Linear, etc.) — identical behavior
- `_LIGHT_DEFAULT` for truly-unknown brands — still `#2563EB` (tests assert this)
