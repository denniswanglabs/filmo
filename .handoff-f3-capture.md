## What was changed

**File:** `capture_screenshots.py` only (adapters.py NOT touched)

### Fix 1 — Distinct inner page via priority-ranked route discovery

`_discover_routes()` now sorts candidates into two buckets before returning:
- **priority** — routes whose path contains any of: `pricing`, `features`, `feature`, `products`, `product`, `solutions`, `solution`, `platform`, `how-it-works`, `why`, `enterprise`, `for-business`, `for-teams`, `use-cases`
- **fallback** — all other valid same-origin routes

Priority routes are returned first, so the 2nd screenshot is more likely to be a real product/pricing page rather than e.g. `/about` or the first footer link.

Additionally the skip-word list was expanded to include `news`, `events`, `about`, `team`, `jobs`, `partner`, `affiliate`, `download`, `app-store`, `play-store`, `social`, `community` — these are low-content pages that add noise.

**Fallback scroll shot:** When no valid inner route is found (all routes blocked or geo-redirected), the 2nd shot is now a scrolled-down view of the homepage (`label: "home-scroll"`) rather than an identical re-shot of the hero. Uses `window.scrollTo(0, scrollHeight * 0.45)` before screenshotting.

### Fix 2 — Force en-US locale

`browser.new_context()` now sets:
- `locale="en-US"`
- `extra_http_headers={"Accept-Language": "en-US,en;q=0.9", "Accept": "text/html,..."}` 
- Full desktop UA string `Chrome/124.0.0.0` (was missing the patch version)

**Geo-redirect detection added:** After navigation, `grab()` checks `page.url` against `_GEO_LOCALE_RE` — a regex matching `/tw/`, `/zh-tw/`, `/zh-cn/`, `/fr/`, `/de/` and 20+ other non-English locale segments. If the final URL matches, the route is skipped (logged to stderr) and the next route is tried, eventually falling back to the scroll shot. This handles Shopify's server-side geo-redirect that ignores Accept-Language headers.

### Fix 3 — Bot-block detection

`_is_blocked(page)` detects block/challenge pages via:
1. Title + body text (first 2000 chars) containing any of 12 block signals: "access is temporarily restricted", "access denied", "are you a robot", "captcha", "cloudflare", "just a moment", "ray id", etc.
2. **Body text < 300 chars including empty (len == 0)** — this catches TripAdvisor's JS-heavy SPA that returns an empty body, and Cloudflare waiting-room pages.

When a block is detected: retry once with a fresh `ctx.new_page()`, settle 2s. If still blocked, return `None` (no screenshot saved). The manifest will have `ok: false` and `count: 0`, so downstream `generate_screenshots()` in `adapters.py` falls back to the synthetic card instead of saving a screenshot of the block page.

## Known limitation

Shopify's nav links are ALL geo-redirected to `/tw/...` when accessed from Taiwan, so even with en-US locale the inner-route fallback fires and we use the scroll shot. The scroll shot is visually distinct (mid-page content) but it's not a separate product page. To get a genuine `/pricing` route for Shopify.com from Taiwan, you'd need a proxy or `geolocation` spoofing — not attempted here ($0 constraint).
