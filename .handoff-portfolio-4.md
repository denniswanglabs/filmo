## ===== v3-vs-v2 SHOPIFY VERDICT (the headline result) =====

**Does the green steer now? — YES, the color-DOMINANCE lever WORKS as a steer; the SPECIFIC hue does NOT match olive.**

- **v2 (`shopify-v2.mp4`):** rim read warm amber/copper (left edge) + iridescent purple-blue (right
  edge). The frame had NO single dominant brand color — off-brand chaos. (per `.handoff-portfolio-3.md`.)
- **v3 (`shopify-v3.mp4`):** the ENTIRE frame is now bathed in ONE green-family color — bright green
  rim glow on the hero monitor, green volumetric haze, green floor reflection, green background
  gradient. ZERO amber/copper/purple anywhere. The "single dominant color of the whole frame" cue did
  exactly what it says. This is a dramatic, decisive improvement over v2.
- **BUT the hue landed TEAL/EMERALD (~170°), not Shopify olive (~96°)** — a ~74° shift toward cyan.
  Quantified (sat·val-weighted dominant-hue bins across f0.5/f3.0/f5.5): all three frames peak at
  **170° = teal**, with green (160°) second. Target olive `#5E8E3E`/inject `#468E15` = 96°.
- **Why:** the plain-English word "green" pulled the model to its PROTOTYPICAL bright emerald/teal
  "green," ignoring the warm-olive specificity of the `#468E15` hex. The dominance phrase amplifies
  the NAME (repeated 5×) far more than the hex (1×), so a name that doesn't match the brand's exact
  hue now steers HARD to the wrong shade. v2 under-steered; v3 over-steers to the named prototype.

## Is color-dominance the answer for MUTED hues?
**YES as a STEER — it reliably makes the brand-family color dominate the whole frame and kills the
off-brand amber/purple chaos. PARTIAL on hue ACCURACY — faithful only when the brand hue sits near a
prototypical named color.**
- Slack aubergine ≈ "magenta" (a prototype) → ~9° accurate. WIN.
- Shopify olive sits BETWEEN "amber" and "green" prototypes → naming it "green" yanked it to bright
  teal, ~74° off. The 12-name hue wheel is too coarse for in-between hues, and the repeated NAME now
  out-votes the hex.
- **Net:** color-dominance is the right lever for "make the brand color dominate" (definitively beats
  v2). It is NOT yet sufficient for hue-accuracy on a brand whose hue falls between named prototypes.

## Recommended next lever (for the orchestrator; NOT done — read-only this iter)
The name now over-steers. Two candidate fixes for olive-class in-between hues:
1. Use a more SPECIFIC name for in-between hues — e.g. map `#468E15` to "olive green" / "yellow-green"
   / "warm green" rather than bare "green," so the prototype the model anchors on is closer to the
   brand hue. (Pure prompt/`_color_name` change.)
2. De-emphasize the bare name and re-weight toward the hex + a hue-qualifier ("a warm yellow-green,
   not a cool teal") to fence the model away from the emerald/teal prototype.
Slack needs no change. Validate any olive fix with ONE more Shopify re-roll (a future PAID iter).
