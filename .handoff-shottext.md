# Handoff: shot-text (text + screenshot on apple-screenshot scenes)

## Goal
Screenshot scenes showed ONLY a bare image. Now they show a prominent grounded
value-prop HEADLINE composed WITH the screenshot, in the orinovate-kinetic-light style.

## Root cause (BOTH archetype + pipeline)
1. **Archetype** (`studio/src/timeline/archetypes/AppleScreenshot.tsx`): the only text
   it rendered was `data.caption` — the captured URL — in tiny muted mono, double-duty
   as the browser address bar AND an under-card line. No prominent headline element existed.
2. **Pipeline** (`style_fill.py::_shape_screenshot`): only carried `imageSrc/frame/caption`
   and set `caption` = the page URL. It DISCARDED the threaded VO beat (`data._text`, set
   by `build_props` from the line narrated over the scene, e.g. "Breaking tech news,
   in-depth reviews, and sharp analysis every day."). The grounded value-prop never
   reached the archetype.

## What changed

### Pipeline — `style_fill.py`
- New `_shape_screenshot` now derives a `headline` (separate from `caption`/URL) using the
  EXISTING headline-quality machinery `_grounded_headline(...)` — applies nav-label / weak /
  prompt-artifact rejection + the positive `_looks_like_headline` test.
  - Source priority: threaded VO beat (`data._text`) -> scene `brief` (only if NOT a
    capture/CTA/artifact stage-direction) -> brand tagline -> "" (no headline).
  - Final guard: headline never equals the address-bar URL caption (no duplication).
- New helper `_is_capture_stage_direction()` (+ phrase/opener/noun tables near
  `_is_cta_stage_direction`) so a screenshot scene's camera-direction brief ("Real
  captured homepage of The Verge in a branded browser card") and any leaked capture
  narration in the VO can NEVER become the headline.
- `caption` (URL for the address bar) behavior is unchanged.

### Composition contract — `studio/src/timeline/types.ts`
- Added `headline?: string` to `SceneData` (documented as the grounded value-prop,
  NEVER the URL).

### Archetype — `studio/src/timeline/archetypes/AppleScreenshot.tsx`
- Renders a prominent kinetic headline ABOVE the card: optional accent kicker + a 46px
  `theme.text` display headline, rising on a `headlineAt` cue (just before card settle)
  with the existing `appleRise` motion.
- Headline element carries `data-scene-id={sceneId}` + `data-field="headline"`
  (click-to-select/editable). The existing under-card URL caption div was also
  instrumented with `data-field="caption"` so BOTH stay addressable.
  NOTE: brief asked for `data-field="caption"` on the new text, but the new element edits
  `data.headline`, so `data-field="headline"` is the correct field-keyed value (matches
  the editor's data-field convention). Caption div keeps `data-field="caption"`.
- Backward-compatible: empty/absent headline -> nothing renders, card stays centered
  (verified byte-clean below).

## Out of scope (untouched, per brief)
- `studio/editor/` and `dashboard/` NOT modified. The editor's `EditPanel.jsx` does not
  yet list a `headline` input for apple-screenshot — that is an editor-config follow-up,
  outside this task's scope. The new `data-field="headline"` is runtime-only and does not
  break the editor build.
