# .handoff-editor-integration — fold the video editor INTO Walk Studio (one app, :3030)

_2026-06-22 (session 5). The standalone editor (Vite app on :3040) is now served BY the
dashboard on :3030 and reachable from a delivered build's "Edit video" button. No second
process, no second port. Additive + backward-compatible; the :3040 dev server still works._

## What changed (and why it's clean)
The dashboard server (`dashboard/serve.py`) already serves the WHOLE project root statically
with HTTP Range support, and Remotion's `staticFile()` honors `window.remotion_staticBase`.
So the editor folds in with zero asset copying:

1. **`studio/editor/vite.config.js`** — `base:"/editor/"`, `build.copyPublicDir:false`
   (keeps the ~600 MB of run screenshots OUT of the bundle), `build.outDir:"dist"`.
2. **`studio/editor/package.json`** — added `"build": "vite build"`.
3. **`studio/editor/src/main.jsx`** — in PROD only, `window.remotion_staticBase="/studio/public"`
   so the in-browser Player resolves `staticFile("shot-x.png")` to the dashboard-served
   `/studio/public/shot-x.png`. In `vite` dev the dev server serves publicDir at root, so the
   base is left unset (default `/shot-x.png`) — both work.
4. **`studio/editor/src/App.jsx`** — fetches namespaced to `/api/editor/{runs,props,save,render}`;
   on load reads `?run=<id>` from the URL and deep-loads that run (overrides DEFAULT_RUN).
5. **`studio/editor/server-api.js`** (the :3040 dev middleware) — same `/api/editor/*` route
   names so dev parity holds. Header comment updated.
6. **`dashboard/serve.py`** — the integration core:
   - `_route_editor()`: `/editor` → 301 `/editor/`; `/editor/<rel>` → rewrites `self.path`
     to `/studio/editor/dist/<rel>` (SPA-shell fallback to `dist/index.html` for `/editor/`
     and any non-file path, so `?run=` deep links load). Traversal-guarded (`".." `→ shell;
     non-file→shell). Called from both `do_GET` and `do_HEAD`.
   - `_api_get` + `do_POST`: route `/api/editor/{runs,props,save,render}` to four new methods
     that MIRROR `server-api.js` exactly (read/write `runs/<id>/`, `safe_run_dir()`-sanitized).
   - `_api_editor_render` streams plain-text status lines and spawns the SAME `remotion render`
     the pipeline uses (`_editor_render_cmd`, byte-identical to build_runner) with `Connection:
     close` so the browser's fetch-stream reader gets EOF. Server is threaded → a multi-minute
     render never blocks the dashboard.
7. **`dashboard/app.js`** `deliveredHero()` — added an `<a class="dh-edit" href="/editor/?run=<id>">
   Edit video</a>` after Download MP4 (icon `i-layers`). **`dashboard/styles.css`** — `.dh-edit`
   styled as a NEUTRAL secondary (like Copy link); coral stays rationed to the Download button.
8. **`start-walk-studio.command`** — step "0b" ensures the editor bundle exists (builds if
   `studio/editor/dist/index.html` is missing; non-fatal). **`.claude/launch.json`** —
   `hermes-dashboard` got `"autoPort": false` (the dashboard MUST own :3030 for the Stripe
   return URL).

## After editing the editor source OR the studio compositions
Rebuild the bundle (the dashboard serves the BUILT snapshot of the compositions; per-run
variation lives in props.json, which is loaded live):
```
cd studio/editor && npm run build
```
The render/export path uses the LIVE TSX via `remotion render`, so exports always reflect the
current compositions regardless of when the preview bundle was last built.
