## CROSS-CUTTING FINDING — ledger clobber when WS_VO_ENGINE=ON (regression, money path NOT broken)
- ROOT CAUSE: orchestrate() (orchestrator.py L183) constructs its OWN Ledger and writes the full delivered record (scenes/pnl/gate verdicts, status=delivered) to runs/<id>/ledger.json. After orchestrate returns, build_runner run() (build_runner.py L257-269) appends the VO-ENGINE event to its STALE in-memory run-level `led` (which only holds planning+payment events) and calls led.write(led_path) at L266 — OVERWRITING orchestrate's rich ledger. Net effect when engine ON: persisted ledger.json loses scenes/pnl/gate events and is stuck at status=running/phase=producing; never flips to delivered.
- PROOF: runs 1 & 2 (engine ON) → ledger scenes=[], pnl=null, status=running. Run 3 (engine OFF, no clobber) → scenes=5, pnl=set, status=delivered. Standalone orchestrate (no build_runner) → delivered with full gate verdicts.
- IMPACT: the EXECUTION is correct (clips produced, gate fired, payment paid) but the DASHBOARD-FACING ledger for an engine-ON build (the default dashboard path!) under-reports: shows no scenes/pnl and never marks delivered. The dashboard would render a perpetually "producing" run with a finished video on disk.
- SUGGESTED FIX (for orchestrator/impl agent, NOT applied here — read-only verify): build_runner should reload the on-disk ledger written by orchestrate before appending the VO-ENGINE event (ledger_mod.Ledger.load(led_path)), OR write the VO-ENGINE note via the orchestrate-returned ledger, instead of re-writing the stale run-level `led`. Mirror the pattern already used in _record_failure (which reloads from disk first).
