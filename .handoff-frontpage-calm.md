# Front-page composer — Company URL field made CALM (no coral alert)

## Problem
On the front-page composer, the middle "Company URL" input showed a coral border
(read like a red-alert). The top (goal) + bottom (emphasis) inputs were correctly
neutral borderless `--bg-2` wells. Goal: make all three calm; coral reserved for
the play button + selected quality card.

## Root cause (traced)
`focusBuildUrl()` in app.js (called on "New build" click via newBuild() and on the
hidden #hero-start) does two things to #build-url:
1. `u.focus()` — programmatic focus.
2. `u.classList.add("nudge")` — one-shot pulse animation.

The coral came from the `@keyframes in-nudge` (styles.css), which set
`border-color: var(--amber)` (coral) at 0%/30%/100% for the full 0.9s. The input's
base border is `1px solid transparent`, so the coral border-color painted a visible
coral box on the URL field for the whole animation. The screenshot caught it mid/post
nudge. The "coral placeholder" was an optical read — placeholder color is `--ink-4`
(neutral grey-blue); there is NO coral placeholder rule.

NOTE: the same `in-nudge` keyframe is reused on #build-goal by the example-chip
click handler (app.js init), so fixing at the keyframe level fixes both consistently.

## Fix (file:line)
1. styles.css `@keyframes in-nudge` (~line 1067) — replaced the coral border pulse
   with a CALM neutral lift: `border-color: transparent` at all stops + a faint
   neutral box-shadow (`rgba(20,23,28,.06)`) that fades. No coral anywhere in the
   pulse now.
2. app.js `focusBuildUrl()` comment updated to document the calm behavior.

## Untouched (kept intact from prior de-AI pass)
- `.cmp-in` base: borderless `--bg-2` well, transparent border, `--ink-4` placeholder.
- `.cmp-in:focus` (line 617): neutral well brighten, no coral (mouse/programmatic).
- `.cmp-in:focus-visible` (line 619): faint coral ring — KEYBOARD focus only. KEPT.
- Play button gradient/coral, selected `.q-opt.is-on` coral — KEPT.
