## Badge logic

- **Bookend archetypes** (no badge): `hero-title`, `apple-statement`
- **Content-beat archetypes** (get badge): `apple-screenshot`, `apple-hero`, `apple-registry`, `card-ui`, `explainer-card`, `walkthrough-player`
- Index is 1-based, zero-padded: `actNum(1) → "01"`
- Label is `data.kicker` trimmed to ≤2 words, uppercased. Fallbacks: registry uses `data.heading`; walkthrough uses `data.overlayTitle`
- Badge format: `"NN — LABEL"` (em-dash, space-padded)
- Style: fontSize 22, fontWeight 700, letterSpacing "0.18em", textTransform "uppercase", brand accent color, fontMono — matches reference film eyebrow style

## Key implementation note

The badge must be the **last** child of the outer `AbsoluteFill` in archetypes that have a mesh/background `AbsoluteFill` child (Screenshot, Hero, Registry, Walkthrough). DOM order = stacking order: later children paint on top. ExplainerCard and CardUi do not have a full-coverage `AbsoluteFill` child, so placement there is flexible.
