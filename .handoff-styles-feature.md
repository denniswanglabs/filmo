# Handoff — Real style differentiation (snappy/standard/cinematic)

Iteration 2 of the overnight loop. Implements the iter-1 proposal: make the three
style pills produce genuinely different videos (scene count / hold durations / cut
rhythm), while keeping **standard byte-identical to today's default**.

## Design (lowest-touch, standard-safe)

1. **`serve.py:_api_build`** reads the existing `pace` field (dashboard already
   POSTs the pill value there) → maps to `--style {snappy,standard,cinematic}` →
   appends to the `build_runner.py` cmd. (NOT editing app.js — UI agent owns it.)
2. **`build_runner.py`** gains `--style`; `run(..., style="standard")`:
   - exports `HERMES_STYLE` env (carried into the codegen render layer)
   - passes `style` to `plan_job.plan_job(...)`
   - runs a **deterministic re-timer** on the returned plan (the LLM backstop)
3. **`plan_job.plan_job(style=...)`** injects per-style guidance into the planner
   SYSTEM_PROMPT (snappy = more+shorter, cinematic = fewer+longer). standard = no
   injection (today's prompt verbatim).
4. **Deterministic re-timer** (`plan_job._restyle_durations`) redistributes the
   FIXED `target_duration_s` per style so the total stays ~30s but holds change.
   standard = identity (untouched).
5. **`remotion_codegen.py`** reads `HERMES_STYLE` env for a per-style
   motion/ease INTENSITY (snappy = faster entrance eases; cinematic = slower).
   When env is unset or "standard" → today's exact constants → byte-identical.

## SAFETY INVARIANT
standard: no prompt injection, no re-time, no intensity change → reproduces today's
exact output. Only snappy/cinematic vary. Verified by: test suite GREEN +
standard build matches a default (no-style) build.

### Per-style logic
- snappy   : prompt asks 6-8 scenes / 2-4s holds + a motion_graphic; re-timer caps
             content holds toward 3s; SPD=0.6 (faster eases). Template = 7 scenes.
- cinematic: prompt asks 4-5 scenes / 6-9s holds + prefer seedance; re-timer
             compresses titles to 2s and pushes content holds toward 10s; SPD=1.45
             (slow eases). Template = 4 scenes.
- standard : NO prompt injection, identity re-timer, SPD=1.0 — reproduces today.

### Known limit (honest)
At 30s the schema floor (exactly 1 walkthrough + 2-3 cinematic = >=3 content scenes)
caps how few cuts cinematic can have. snappy is robustly distinct (count + holds).
cinematic-vs-standard separates by hold length (title compression + max-budget holds
+ SPD), which is real but smaller when Nemotron hands both the same 3-content shape.
The deterministic re-timer guarantees a structural difference (2s vs 3s titles,
9s vs 8s holds) even on an LLM collision, so the 3 never render identical.
