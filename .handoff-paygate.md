## Phase 1: BACKEND FLOW — DONE + VERIFIED ($0)

### Files changed
- `build_runner.py` — restructured `run()` to insert the gate between plan and
  produce:
  1. initial 'planning' ledger (unchanged behavior).
  2. `plan_job.plan_job()` -> the storyboard.
  3. NEW `_price_plan(plan, run_dir)` — writes plan.json + `producer.cmd_estimate`
     to get `suggested_price_cents` BEFORE production; sets ledger `plan` + `pricing`.
  4. NEW `_payment_gate(...)` — `stripe_earn.create_checkout_session(run_id,
     price_cents, product_name="<brand> promo video")`; writes phase=awaiting_payment
     + status=running + the `earn` block; flushes so the dashboard renders the gate;
     then POLLS `stripe_earn.get_session_status()` every 2.5s, writing
     earn.payment_status on change, until 'paid'/'no_payment_required' OR a 15-min
     wall-clock cap -> on timeout phase=payment_timeout / status=failed + error event.
  5. on paid: `event("money","payment received — $X.XX")`, phase=producing, then
     `orchestrator.orchestrate(plan, run_id, mode=<mode>, overlays=..., earn=earn)`.
  - DEV affordance: `PRODUCER_SIMULATE_PAID=1` -> poll resolves to 'paid' immediately
     (real test session still created). With `--mode mock` => plan->gate->(sim
     paid)->mock production->delivered, all $0.
  - Imports added: `producer`, `stripe_earn`.
- `orchestrator.py` — `orchestrate(...)` gained an optional `earn=None` param. When
  a pre-paid earn block is passed (from the gate), it is preserved on the ledger
  (instead of minting a fresh `stripe_money.earn` Payment Link) and logs
  "EARN: payment received via Stripe Checkout". `earn=None` keeps the OLD behavior
  (demos / direct orchestrator runs unchanged).

### New ledger `earn` fields (awaiting_payment -> paid)

  price_cents, currency, product_name:"<brand> promo video", livemode:false,
  payment_status:"unpaid"|"paid"|"no_payment_required" }`.
New phases: `awaiting_payment` (gate shown), `payment_timeout` (failed).
