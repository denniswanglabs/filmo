## Geometry intentionally SKIPPED (text + click-to-select only) and why
- card-ui, explainer-card, apple-registry, walkthrough-player: their primary
  elements are absolutely-positioned / CSS-grid layouts (fixed left/right/top/bottom
  insets, grid templates). A single width/height slider can't map to one literal
  without restructuring the layout, which risks changing rendered output. Per the
  brief, geo is OPTIONAL and was skipped here; click-to-select + text/list editing
  (the priority) is fully wired. card-ui/explainer-card list items are editable via
  the Lists section instead.
- apple-hero: only font-size geo added (titleFontSize/subtitleFontSize). Its product
  plate is padding-sized, not fixed W/H, so no plate width/height slider (the old
  GEO entry's plateW/plateH were no-ops — the component never read them — so they
  were removed to avoid dead sliders).

## Backward-compat
- All `data-*` attributes are inert (no layout effect).
- New geo reads: AppleHero.titleFontSize??140, subtitleFontSize??32;
  AppleStatement.statementFontSize??116. Each fallback equals the prior literal, so
  with geo absent (every production run) output is byte-identical.
- AppleStatement lines were wrapped in a selectable container with the SAME flex
  gap:6 the parent used; footnote keeps marginTop:36. Net spacing unchanged.
