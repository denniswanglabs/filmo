### Root cause (why old parser failed)
`_extract_job_id` (old) only checked `d.get("id") or d.get("job_id")` on a dict (or first list
elem). It returned `None` (silently) on ANY other shape and, critically, the raise discarded the
raw response — so the actual shape is unknown AND the paid job id was lost. The most likely real
cause: create-without-wait returns a shape the old 2-key/first-elem lookup missed (e.g. a wrapper
object whose ids live under a different/plural key, or a list whose id lives deeper), OR a bare
UUID string (json.loads of a bare quoted string → str, `.get` path skipped → None).
