            data:{...SceneData per archetype} }] }

## Registry design — adding a NEW style = ONE entry in STYLES{}
Each `Style(name, role_map, default_archetype, shapers, theme_fn)`:
- role_map: plan scene role/type -> archetype id.
- shapers: {archetype -> fn(plan_scene, brand) -> SceneData}.
- theme_fn: brand_theme -> Timeline theme block (per-template normalizer).
orinovate-kinetic-light: open/hero/title/close/cta -> HeroTitle;
feature/capability/cards -> CardUi (2x2 from brand.features). No other code changes
to add a style.

## Per-template adapter (spec requirement) — theme normalization
`_theme_kinetic_light` accepts BOTH the hand fixture (palette.{bg,accent,navy,text})
AND brand_extract.py's shape (palette.{bg,ink,accent,accent2,success},
fonts.{display,mono}) via per-key alias fallback. Cards accept {label,value,sub}
OR {title,sub}. So style_fill consumes either brand source.
