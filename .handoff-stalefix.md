# Stale-fix handoff — dashboard stuck on dead "BUILDING…" view

Date: 2026-06-22

## Symptom
Reloading the dashboard (http://localhost:3030) opened a stuck "BUILDING… deciding the
storyboard…" view for a DEAD build (`build-orinovate-531243`) instead of the home/composer.

## Root cause
`dashboard/serve.py` `_api_active()` returned EVERY run whose `runs/<id>/ledger.json` had
`status == "running"`, with no staleness check. Four runs were frozen at `status:"running"`
from 1–2.5 days ago after their `build_runner.py` died without finalizing. No live
`build_runner.py` process existed. `app.js init()` polls `/api/active`, calls
`beginPoll(d.active[0].run_id)` on the first entry, and spins forever.

## Fix applied

### Part A — `_api_active` liveness guard (dashboard/serve.py)
- Added module constant `_ACTIVE_FRESHNESS_SECS = 180` (just above `_RANGE_RE`).
- `_api_active()` now reports a run as active ONLY if `status == "running"` AND the freshest
  mtime of `runs/<id>/build.log` and `runs/<id>/ledger.json` is within 180s of now. Stale
  "running" runs are skipped. Response shape unchanged: `{"active":[{"run_id","phase"}]}`.
- 180s comfortably survives a slow render/stitch phase (those still touch files inside the
  window) while excluding anything minutes-to-days old.
- Backup: `dashboard/serve.py.pre-stalefix.bak`.
- `python3 -m py_compile dashboard/serve.py` → OK.

### Part B — one-time sweep (sweep_stale_ledgers.py, kept in repo)
Ran once. Same 180s window. Backed up each ledger to `ledger.json.pre-stalefix.bak`, then
flipped status, preserving all other fields. All 4 had `final.mp4` but `stitch == None`
(the delivered view requires `status=="delivered" && l.stitch`, app.js:600), so all → `failed`:

| run_id                  | old     | new    | final.mp4 | stitch | reason added |
|-------------------------|---------|--------|-----------|--------|--------------|
| build-orinovate-531243  | running | failed | yes       | none   | yes |
| demo-parallel-stripe    | running | failed | yes       | none   | yes |
| iv-premium-201258       | running | failed | yes       | none   | yes |
| iv-standard-200849      | running | failed | yes       | none   | yes |

`failure_reason`: `"abandoned — build process died before finalizing (auto-swept)"`.
Nothing deleted. No run remains at `status:"running"`.

### Front-end
No change needed. `app.js init()` (line 2458) already falls through to `loadIndex(false)`
(home/composer) when `/api/active` is empty; `beginPoll` only fires when `d.active.length`.
`node --check dashboard/app.js` → OK.

## Verification
- Server restarted on :3030 (new PID confirmed via lsof). `GET /` → 302 → dashboard 200.
- `curl http://localhost:3030/api/active` → `{"active": []}` (no phantom builds).
- Guard proven with a throwaway run `zz-stalefix-guardtest`: fresh files → appears in
  `/api/active`; backdated 10-min files → excluded. Test run removed cleanly.

## Notes for next time
- The sweep script is reusable and idempotent (won't clobber an existing `.pre-stalefix.bak`,
  won't touch live runs). Safe to re-run if more builds get orphaned.
- Dashboard left RUNNING on :3030.
