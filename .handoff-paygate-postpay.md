### Why the landing is broken — TWO bugs
1. **serve.py**: `_redirect_root()` only matches `self.path in ("/", "/index.html", "")`.
   The success URL is `/?paid=build-orinovate-edf804`, so `self.path` =
   `/?paid=build-orinovate-edf804` — NOT matched → falls through to `send_head`, which sees
   the project root dir and returns an HTML **directory listing** (verified via curl: HTTP 200
   "Directory listing for /"). THAT is the broken page Dennis saw.
2. **dashboard/app.js**: `init()` never reads `location.search`. Even after reaching the
   dashboard it ignores `?paid=<id>` / `?cancelled=<id>` and auto-selects a decline/first run.

### success_url / cancel_url
- stripe_earn.build_session_params: success=`{base}/?paid=<job_id>`, cancel=`{base}/?cancelled=<job_id>`.

## FIX PLAN ($0)
- serve.py `_redirect_root`: strip the query string before matching `/` and preserve it on the
  302 Location so `/dashboard/index.html?paid=<id>` is reached. (serve.py is served from disk;

  302 fix needs a restart to take effect. ALTERNATIVE: also make app.js robust so it works even
  if the user lands on the dir listing? No — the dir listing is served by Python, JS can't run.

- app.js: on init, parse `?paid=<id>` → select that run, resume polling/show its state with a

## FIXES APPLIED ($0, no rebuild, no spend)

1. **dashboard/app.js** — added `handleCheckoutReturn()` (called first in `init()`): parses
   `?paid=<id>` / `?cancelled=<id>` from `location.search`.
   - `?paid=<id>`: pins the run, shows a "PAYMENT RECEIVED — producing your video"
     confirmation, then `beginPoll(<id>)` resumes the live view → transitions to the live
     production view (running), the delivered video (delivered), or a clear failure carrying
     the real ledger error (failed). Never a bare page.
   - `?cancelled=<id>`: graceful "PAYMENT CANCELLED · no charge" card with a "View the build"
     button back to the run; not a dead page.
   - Strips the query from the address bar via `history.replaceState` so a refresh doesn't replay.
   - Fixed `finishBuild()` failure branch: now pins `state.selected` + refreshes the rail +
     shows the run (previously it only set `detail.innerHTML` and let a pending `loadIndex`
     auto-select a different run — the race that made the paid run land on the wrong/blank view).
   - Guarded `loadIndex()`: when a live poll owns the selected run (`state.building ===
     state.selected`) it skips selectRun so it can't overwrite the BUILDING/production view.

2. **stripe_earn.py** — `success_url`/`cancel_url` now point at
   `http://localhost:3030/dashboard/index.html?paid=<id>` (was `/?paid=<id>`). This sidesteps
   the serve.py directory-listing bug for ALL future builds with NO server restart needed.

3. **dashboard/serve.py** — `_redirect_root()` now splits off the query string before matching
   `/`, and carries the query through the 302 to `/dashboard/index.html?<query>`. Fixes the
   directory-listing for any bare `/?paid=…` (old links / manual hits). DEFENSE IN DEPTH —
   **takes effect only after Dennis restarts serve.py** (it's a long-lived disk-served process;
   per the brief I did NOT restart it). Not required for new builds because of fix #2.

4. **runs/index.json** — was stale (`build-orinovate-edf804` listed as `running` while its
   ledger said `failed`). Regenerated from the ledgers via the canonical
   `orchestrator._update_index` (no run modified). Now reads `failed`.
