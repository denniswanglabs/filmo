# Duration-fix handoff (VO-driven engine honors target_duration_s)

## Bug (confirmed with evidence)
Real run `runs/build-orinovate-00ef35/`: plan `job.target_duration_s=30`, plan scenes
`duration_s` sum = 2+9+9+8+2 = 30. But `timeline.json total_frames=254` (~8.5s) and
`final.mp4` = 8.512s. Cause: `build_timeline.build_timeline` set each scene length =
VO word span ONLY, ignoring plan `duration_s` / `target_duration_s`. VO is only 8.48s,
so all 5 scenes flash by (31/77/38/38/70 frames) -> reveals never finish -> "blank".

## Fix
1. `build_timeline.py` — scene length = `max(plan duration_s frames, VO span frames)`.
   - plan `duration_s` is the FLOOR (scene HOLDS for planned time); never shorter than VO.
   - in/out = cumulative sum of these lengths. Total >= target_duration_s.
   - If `target_duration_s` present and laid-out total < target, pad the LAST scene so
     total == target_duration_s exactly. (>= target if a beat VO overran its slot.)
   - Per-scene audio: emit `audio` block per scene = {src (per-beat mp3), at_frame=in_frame,
     start_from_s}. Beat audio starts at the scene's NEW in_frame so VO lands on its scene.
   - Word-anchored cues stay relative to scene start (rebased by slide offset, as before).
   - Graceful fallback: if plan target/duration missing -> old VO-span behavior.
2. `style_fill.py` — pass plan job + per-scene duration_s into build_timeline; stage each
   per-beat mp3 into studio/public and rewrite each scene.audio.src to public-relative.
3. `studio/src/timeline/Timeline.tsx` + `types.ts` — render per-scene `<Audio>` at scene
   in_frame (Sequence) instead of one continuous `<Audio>` from frame 0. Keep a fallback
   to the single top-level audio_path when scenes carry no per-scene audio.

## Per-beat audio convention
Full VO at `<run>/voiceover.mp3`; per-beat at `<run>/voiceover.beat{NN}.mp3` (00-indexed,
plan/beat order). Durations match beat spans (beat00=1.056s ... beat04=2.088s).
